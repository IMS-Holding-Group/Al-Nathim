## 1. المقدمة

**الناظم** مشروع تخرج جامعي يقدّم مساعدًا ذكيًا يجيب على أسئلة طلاب جامعة تبوك حول اللوائح والأنظمة الأكاديمية الرسمية. يعتمد النظام على نصوص حقيقية مستخرجة من لائحة الدراسة والاختبارات ودليل الطالب الأكاديمي «مسيرتي»، ثم يبحث عن المقطع الأنسب لسؤال الطالب، ويرسله مع السؤال إلى نموذج ذكاء اصطناعي عبر خدمة OpenRouter ليُصاغ جواب رسمي بالعربية الفصحى مع ذكر المصدر.

الفكرة الأساسية ليست «توليد معرفة عامة»، بل تقييد الإجابة بما ورد في اللوائح فقط. بهذا يقل خطر اختراع معلومات غير صحيحة، ويصبح الجواب قابلاً للتحقق لأن النظام يعرض اسم اللائحة ورقم المادة أو العنوان الذي استُند إليه.

الواجهة موجهة للطالب النهائي: صفحة محادثة بسيطة بلغة عربية واتجاه من اليمين إلى اليسار، بهوية بصرية مستوحاة من شعار الناظم (كحلي غامق وذهبي وأبيض). لا يوجد تسجيل دخول؛ يكفي فتح الصفحة وكتابة السؤال.

### 1.1 المشكلة

اللوائح الجامعية طويلة وصياغتها قانونية، ويصعب على الطالب الجديد أو حتى المستمر أن يجد بسرعة إجابة دقيقة عن أسئلة مثل: شروط الاعتذار عن فصل دراسي، نسبة الغياب المؤدية للحرمان، ضوابط التحويل الداخلي، أو متطلبات مرتبة الشرف. البحث اليدوي في ملفات PDF أو أدلة مطبوعة يستغرق وقتًا وقد يؤدي لفهم غير مكتمل إذا قرأ الطالب فقرة بمعزل عن سياقها.

### 1.2 الحل

يعتمد الناظم أسلوب **الاسترجاع المعزّز بالتوليد (RAG)**. أولًا يُقسَّم نص اللائحة إلى مقاطع منطقية تُحفظ في قاعدة بيانات SQLite. عند ورود سؤال، يُطبَّع النص العربي ويُحسب تطابق الكلمات الدلالية مع كل مقطع. أفضل مقطع يُرفق مع السؤال في طلب إلى نموذج لغوي عبر OpenRouter (مع إمكانية استخدام Gemini كبديل). النموذج يُلزم بالإجابة من المقطع فقط وذكر المصدر في النهاية.

### 1.3 الهدف من المشروع

- تمكين الطالب من طرح أسئلة بلغة طبيعية والحصول على إجابة مبنية على اللوائح الرسمية.
- عرض المصدر (اسم اللائحة والعنوان/المادة) بجانب كل إجابة.
- تقديم واجهة رسمية هادئة سهلة الاستخدام دون مكتبات واجهة خارجية.
- بناء هيكل برمجي واضح لمبتدئين: Flask للخادم، SQLite للبيانات، وملفات HTML/CSS/JS ثابتة للواجهة.

## 2. التقنيات المستخدمة

### 2.1 لغة بايثون (Python)

**Python** لغة برمجة عالية المستوى تُستخدم هنا بإصدار **3.10.6** تحديدًا. في هذا المشروع تتولى بايثون: تشغيل خادم Flask، قراءة ملفات الماركداون، تقسيمها إلى مقاطع، البحث النصي، الاتصال بواجهات الذكاء الاصطناعي، وحفظ سجل الأسئلة والإجابات.

### 2.2 إطار عمل فلاسك (Flask)

**Flask** إطار عمل ويب خفيف بلغة بايثون. يسمح بتعريف مسارات (Routes) مثل الصفحة الرئيسية `/` ومسار الواجهة البرمجية `/api/ask`. عند طلب الصفحة يعيد Flask ملف HTML من مجلد `templates`، وعند طلب API يعيد بيانات بصيغة JSON.

مصطلح **JSON**: صيغة نصية لتبادل البيانات بين الخادم والواجهة، مثل `{"success": true, "answer": "..."}`.

### 2.3 قاعدة بيانات SQLite

**SQLite** محرك قواعد بيانات يخزّن كل شيء في ملف واحد (`database/db.sqlite3`) دون الحاجة لتثبيت خادم قواعد بيانات منفصل. مناسب للمشاريع التعليمية والمشاريع متوسطة الحجم. في الناظم يُستخدم عبر مكتبة بايثون المدمجة `sqlite3` مع استعلامات SQL مكتوبة يدويًا (بدون ORM).

مصطلح **SQL**: لغة للاستعلام عن البيانات وإدخالها وتعديلها داخل الجداول.

### 2.4 HTML و CSS و JavaScript

- **HTML**: هيكل الصفحة (الترويسة، منطقة الرسائل، حقل الإدخال).
- **CSS**: التنسيق والألوان والخطوط والهوية البصرية.
- **JavaScript**: التفاعل: إرسال السؤال بـ `fetch`، عرض التحميل، إظهار الإجابة أو رسالة الخطأ، والإبقاء على سجل المحادثة داخل الجلسة في الصفحة.

لا تُستخدم أي مكتبة خارجية للواجهة (لا React ولا Bootstrap ولا Font Awesome ولا CDN للخطوط). الأيقونات رسوم SVG مضمّنة، والخط IBM Plex Sans Arabic محمّل محليًا من مجلد `assets/fonts`.

### 2.5 مفهوم واجهة البرمجة API

**API** (Application Programming Interface) تعني واجهة تسمح لبرنامج بالتخاطب مع برنامج آخر عبر طلبات محددة. في الناظم:

- الواجهة الأمامية ترسل طلب POST إلى `/api/ask` بجسم JSON يحتوي السؤال.
- الخادم يرد بجسم JSON يحتوي الإجابة والمصدر أو رسالة خطأ.

كذلك يتصل خادم الناظم بـ **API خارجي** لـ OpenRouter (أو Gemini) لإرسال النص واستلام رد النموذج.

### 2.6 مفهوم الاسترجاع المعزّز بالتوليد RAG

**RAG** اختصار لـ Retrieval-Augmented Generation. الفكرة:

1. **الاسترجاع (Retrieval):** إيجاد المقطع الأنسب من قاعدة المعرفة (هنا مقاطع اللوائح).
2. **التعزيز (Augmentation):** إرفاق هذا المقطع مع السؤال داخل نص التعليمات (Prompt).
3. **التوليد (Generation):** يطلب من النموذج اللغوي صياغة إجابة اعتمادًا على المقطع المرفق.

بدون RAG قد يجيب النموذج من ذاكرته العامة وقد يخطئ في تفاصيل لائحة جامعة تبوك. مع RAG تصبح الإجابة مربوطة بنص رسمي محفوظ محليًا.

### 2.7 مفهوم OpenRouter

**OpenRouter** منصة وسيطة توفّر وصولًا موحّدًا إلى نماذج ذكاء اصطناعي متعددة عبر واجهة تشبه Chat Completions. في هذا المشروع OpenRouter هو **المزوّد الافتراضي والأساسي**. يُرسل الطلب مع رأس المصادقة `Authorization: Bearer ...` ومعرّف المشروع عبر `HTTP-Referer` و `X-Title`.

**Gemini** من Google يبقى خيارًا بديلًا اختياريًا إذا رُفع مفتاحه في ملف `.env` وتعذّر OpenRouter أو اختير صراحة بـ `AI_PROVIDER=gemini`.

مصطلح **Prompt**: النص الكامل الذي يُرسل للنموذج ويشمل التعليمات والسياق والسؤال.

مصطلح **Temperature**: رقم يتحكم في عشوائية الرد. قيمة منخفضة مثل `0.2` تجعل الإجابة أكثر التزامًا وأقل تأليفًا.

## 3. آلية عمل النظام والخوارزمية

### 3.1 تقسيم اللوائح إلى مقاطع

عند أول تشغيل، إذا كان جدول `regulation_chunks` فارغًا، تقرأ الدالة الملفات من المجلد:

`data/regulations/`

- `laeha_derasah_wa_ekhtebarat.md` باسم لائحة: «لائحة الدراسة والاختبارات»
- `daleel_al_taleb_al_akademi.md` باسم لائحة: «دليل الطالب الأكاديمي (مسيرتي)»

التقسيم يعتمد على عناوين الماركداون:

- العنوان من المستوى الثاني `##` يُعامل كفصل أو قسم.
- العنوان من المستوى الثالث `###` يُعامل كمادة أو عنوان أدق.

كل مقطع يحفظ:

- نص المحتوى تحت العنوان.
- اسم اللائحة في `regulation_name`.
- أقرب عنوان (اسم الفصل أو رقم المادة) في `article_number`.

إذا تجاوز طول المقطع حوالي **1200 حرف**، يُقسَّم إلى مقاطع فرعية متتابعة مع محاولة عدم قطع الجملة في منتصفها (التقسيم عند علامات الجملة أو أسطر جديدة).

### 3.2 تطبيع النص العربي

قبل المقارنة يُطبَّع السؤال ونصوص المقاطع:

- توحيد أشكال الألف: أ، إ، آ ← ا
- توحيد التاء المربوطة والهاء: ة ← ه
- توحيد الألف المقصورة والياء: ى ← ي
- إزالة التشكيل (الحركات)
- إزالة علامات الترقيم الزائدة وتوحيد المسافات

ثم تُستبعد الكلمات الشائعة قليلة الدلالة مثل: من، في، على، إلى، عن، ما، هل، كيف، متى، وغيرها. النتيجة قائمة كلمات دلالية مفيدة للبحث.

### 3.3 البحث النصي وحساب الدرجات

لكل مقطع في القاعدة:

- كل كلمة دلالية من السؤال تظهر في نص المقطع تضيف **نقطتين**.
- ظهورها في العنوان أو اسم اللائحة يضيف **نقطة**.
- إذا تطابقت أكثر من كلمة مختلفة تُضاف مكافأة بسيطة تساوي عدد الكلمات المتطابقة.

يُختار أعلى درجة. عند التساوي يُفضَّل المقطع الأقرب لطول مناسب للقراءة (حوالي 650 حرفًا). إذا كانت أعلى درجة صفرًا يُعاد `None` ويُبلَّغ المستخدم أنه لم يُعثر على مقطع مطابق.

الحل بحث نصي بسيط فقط، بدون مكتبات تضمين متجهي (Embeddings).

### 3.4 بناء الطلب المرسل للنموذج

يُبنى Prompt صارم يأمر النموذج بـ:

1. الإجابة من نص المقطع فقط دون معرفة خارجية.
2. الكتابة بالعربية الفصحى الرسمية.
3. عدم تأليف معلومات.
4. توضيح النقص بأدب إن لم يكفِ المقطع.
5. ذكر المصدر في نهاية الإجابة: اسم اللائحة ورقم المادة/العنوان.

درجة الحرارة تُضبط على حوالي `0.2`. ترتيب المحاولة: OpenRouter أولًا ثم Gemini.

### 3.5 معالجة الاستجابة

- عند النجاح تُعاد الإجابة مع بيانات المصدر إلى الواجهة وتُحفظ في `qa_log`.
- عند أخطاء الشبكة أو المهلة أو المفتاح غير الصالح أو الاستجابة غير المتوقعة تُحوَّل إلى رسائل عربية واضحة تُعرض للطالب.

## 4. بنية قاعدة البيانات

ملف القاعدة: `database/db.sqlite3`

### 4.1 جدول regulation_chunks

يخزّن مقاطع اللوائح المستخدمة في الاسترجاع.

| العمود | النوع | الغرض |
| --- | --- | --- |
| id | INTEGER | مفتاح أساسي يتزايد تلقائيًا |
| chunk_text | TEXT | نص المقطع المستخرج من اللائحة |
| regulation_name | TEXT | اسم اللائحة الرسمية |
| article_number | TEXT | أقرب عنوان (فصل أو مادة) |

مثال بيانات:

- `regulation_name`: لائحة الدراسة والاختبارات
- `article_number`: المادة السادسة عشرة
- `chunk_text`: نص يتحدث عن الاعتذار عن الاستمرار في الدراسة لفصل دراسي...

### 4.2 جدول qa_log

يسجّل الأسئلة والإجابات بعد كل رد ناجح لأغراض المتابعة والتطوير.

| العمود | النوع | الغرض |
| --- | --- | --- |
| id | INTEGER | مفتاح أساسي |
| question | TEXT | نص سؤال الطالب |
| answer | TEXT | نص إجابة النظام |
| created_at | TEXT | وقت التسجيل بصيغة YYYY-MM-DD HH:MM:SS |

مثال:

- `question`: ما نسبة الغياب التي تؤدي إلى الحرمان؟
- `answer`: إجابة النموذج مع ذكر المصدر...
- `created_at`: 2026-07-13 10:15:22

## 6. أهم مقتطفات الكود

### 6.1 تهيئة قاعدة البيانات وتحميل اللوائح

في `database/db.py` تنشئ الدالة `init_database` الجدولين، ثم إذا كان جدول المقاطع فارغًا تستدعي `load_regulation_files` لقراءة ملفات الماركداون وتقسيمها.

```python
cursor.execute("SELECT COUNT(*) AS total FROM regulation_chunks")
if cursor.fetchone()["total"] == 0:
    load_regulation_files(cursor)
```

هذا يضمن أن التحميل الحقيقي للوائح يحدث مرة واحدة عند أول تشغيل، دون تكرار الإدخال في كل مرة يُعاد فيها تشغيل الخادم.

دالة `parse_markdown_chunks` تمر على الأسطر سطرًا سطرًا؛ عند رؤية عنوان `##` أو `###` تغلق المقطع السابق وتبدأ مقطعًا جديدًا بعنوان محدّث. ثم `split_long_text` تضمن ألا يتجاوز المقطع الحد التقريبي 1200 حرفًا دون قص جملة عشوائيًا.

### 6.2 تطبيع النص والبحث

دالة `normalize_arabic` توحّد الحروف وتزيل التشكيل. دالة `extract_keywords` تبني قائمة الكلمات المفيدة. دالة `search_regulation_chunks` تمر على كل المقاطع وتحسب الدرجة كما شُرح في القسم 3.3.

```python
for word in keywords:
    found_in_text = word in norm_text
    found_in_title = word in norm_title
    if found_in_text:
        score += 2
    if found_in_title:
        score += 1
```

إذا بقيت أعلى درجة صفرًا تُعاد القيمة `None`، فيُرجع مسار API رسالة عربية بأن لا يوجد مقطع مطابق.

### 6.3 الاتصال بـ OpenRouter

في `services/ai_service.py` تُبنى رؤوس الطلب لتشمل المصادقة ومعرّف المشروع:

```python
headers = {
    "Authorization": f"Bearer {OPENROUTER_API_KEY}",
    "Content-Type": "application/json",
    "HTTP-Referer": OPENROUTER_SITE_URL,
    "X-Title": OPENROUTER_APP_NAME,
}
```

ودرجة الحرارة منخفضة:

```python
"temperature": 0.2,
```

تُعالج أخطاء المهلة وانقطاع الاتصال ورموز HTTP (مثل 401 للمفتاح غير الصالح و429 لتجاوز الحد) برسائل عربية عبر الدالة المساعدة `_translate_http_error`.

ترتيب المحاولة في `ask_ai`: إذا كان `AI_PROVIDER=openrouter` (الافتراضي) يُجرَّب OpenRouter أولًا ثم Gemini. إذا اختير `gemini` يُعكس الترتيب.

### 6.4 مسار /api/ask

في `routes/api_routes.py`:

1. التحقق من وجود السؤال وطوله.
2. استدعاء `search_regulation_chunks`.
3. استدعاء `ask_ai` مع المقطع المطابق.
4. حفظ السجل عبر `save_qa_log`.
5. إرجاع JSON للواجهة.

عند `ConnectionError` يُعاد رمز HTTP 503 مع رسالة مفهومة. عند أي خطأ غير متوقع يُطبع الخطأ في الطرفية ويُعاد رمز 500 برسالة عامة دون تفاصيل داخلية حساسة.

### 6.5 إرسال السؤال من الواجهة

في `static/js/script.js` يُمنع السلوك الافتراضي للنموذج، ثم يُعرض سؤال المستخدم فورًا (سجل المحادثة داخل الجلسة)، ويظهر مؤشر التحميل، ويُرسل الطلب:

```javascript
fetch("/api/ask", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ question: question }),
})
```

عند النجاح تُعرض الإجابة مع صندوق المصدر (باختلاف لون الخلفية فقط، دون حدود جانبية تمييزية). عند الفشل تُعرض رسالة تنبيه واضحة. الأيقونات SVG مضمّنة كنصوص داخل الجافاسكربت بدل أي مكتبة أيقونات خارجية.

## 7. خطوات التثبيت والتشغيل

اتبع الخطوات بالترتيب. التشغيل يتم ببايثون النظام مباشرة.

### 7.1 تثبيت Python 3.10.6

1. افتح صفحة الإصدار الرسمي:
   https://www.python.org/downloads/release/python-3106/
2. حمّل المثبت المناسب لنظام ويندوز (أو نظامك).
3. أثناء التثبيت فعّل خيار إضافة بايثون إلى متغير PATH إن وُجد.
4. تحقق من الإصدار من الطرفية:

```text
python --version
```

المطلوب ظهور ما يشبه: `Python 3.10.6`

### 7.2 تثبيت المكتبات

افتح الطرفية داخل مجلد المشروع `Al-Nathim` ثم نفّذ:

```text
pip install -r requirements.txt
```

المكتبات الأساسية:

- Flask==3.0.3
- python-dotenv==1.0.1
- requests==2.32.3

### 7.3 الحصول على مفتاح OpenRouter

1. افتح صفحة المفاتيح:
   https://openrouter.ai/keys
2. أنشئ حسابًا إن لم يكن لديك حساب.
3. أنشئ مفتاح API جديدًا مجانًا وانسخه في مكان آمن.
4. (اختياري) إن أردت Gemini كبديل، احصل على مفتاح من منصة Google AI Studio وضعّه لاحقًا في `.env`.

### 7.4 إنشاء ملف .env

ملف `.env` الحقيقي يُنشأ يدويًا في جذر المشروع، ولا يُشارك مع الآخرين لأنه يحتوي أسرارًا.

1. انسخ محتوى الملف النموذجي `.env.example`.
2. أنشئ ملفًا جديدًا باسم `.env` في جذر المشروع.
3. الصق المحتوى وعدّل القيم، وأهمها:

```text
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=ضع_مفتاحك_هنا
```

يقرأ `config.py` هذه القيم عبر `python-dotenv` عند بدء التشغيل.

### 7.5 تشغيل المشروع

من جذر المشروع نفّذ:

```text
python app.py
```

عند أول تشغيل ستُحمَّل اللوائح إلى SQLite وتظهر رسائل في الطرفية بعدد المقاطع. ثم افتح المتصفح على:

http://localhost:5000

اكتب سؤالًا مثل: «ما شروط الاعتذار عن الفصل الدراسي؟» وانتظر ظهور الإجابة مع المصدر.

لإيقاف الخادم اضغط Ctrl+C في نافذة الطرفية.

## 8. مسار الطلب من السؤال إلى الإجابة

1. يكتب الطالب السؤال في حقل الإدخال ويضغط «إرسال».
2. جافاسكربت يضيف رسالة السؤال إلى منطقة المحادثة ويظهر مؤشر التحميل، ثم يرسل POST إلى `/api/ask`.
3. مسار API يتحقق من صحة السؤال.
4. `search_regulation_chunks` يطبّع السؤال ويستبعد الكلمات الشائعة ويحسب درجات المقاطع ويعيد الأفضل.
5. إن لم يوجد تطابق تُعاد رسالة عربية واضحة دون استدعاء النموذج.
6. إن وُجد مقطع، تبني `build_prompt` تعليمات صارمة مع نص المقطع والسؤال.
7. `ask_ai` يرسل الطلب إلى OpenRouter (ثم Gemini عند الحاجة) بدرجة حرارة منخفضة.
8. تُحفظ الثنائية سؤال/إجابة في `qa_log`.
9. تُعاد JSON للواجهة فتُعرض الإجابة ونص المصدر، ويُزال مؤشر التحميل، ويبقى الحوار ظاهرًا ضمن الجلسة في الصفحة.

بهذا يتكامل المشروع من قراءة اللوائح الحقيقية، إلى بناء القاعدة، إلى البحث، إلى التوليد عبر OpenRouter، إلى العرض بالواجهة النهائية بهوية الناظم البصرية الكاملة.
